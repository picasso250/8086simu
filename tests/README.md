# 8086simu 测试指南

本文档旨在为 `8086simu` 项目的测试流程提供指导，以确保代码的正确性和稳定性。

## 如何运行测试

项目提供了一个 `test_file.sh` 脚本，用于编译和运行单个汇编测试用例。

**用法:**
```bash
sh tests/test_file.sh tests/your_test_file.asm
```

脚本会自动处理汇编代码的解析、编译和执行，并根据测试文件中的断言来验证结果。

## 如何编写新的测试用例

所有测试用例都以汇编文件的形式存储在 `tests/` 目录下。

### 1. 创建汇编文件

在 `tests/` 目录下创建一个新的 `.asm` 文件。

### 2. 编写测试代码

编写标准的模拟器汇编代码来测试特定的指令或功能。

### 3. 添加断言

测试的核心是断言。断言用于在程序执行的特定点检查寄存器的值是否符合预期。

**断言语法:**
```asm
;assert(condition)
```

- 断言必须以 `;assert` 开头，并且是一个注释行。
- 判断条件需要用括号 `()` 包围。
- `condition` 是一个标准的 C++ 判断表达式，通常用于检查寄存器的值。例如：`regs[AX] == 10`。

**示例 (`tests/cmp_je_equal.asm`):**
```asm
; tests/cmp_je_equal.asm
MOV AX, 1
MOV BX, 5
MOV CX, 5
CMP CX, BX ; ZF should be set
JE 4       ; Jump over next instruction
MOV AX, 10 ; This should be skipped
ADD AX, 1  ; AX becomes 2
;assert(regs[AX] == 2)
INT 0      ; Halt
```

### 4. 终止程序

使用 `INT 0` 指令来正常终止程序的执行。

## 重要注意事项

### 解析器行为

- **注释:** 汇编解析器会自动忽略以 `;` 开头的注释。然而，为了确保断言被正确识别，请严格遵守 `;assert(...)` 的语法。
- **空格:** 解析器会自动处理指令和操作数周围的空格。

### 常见错误及经验教训

在开发 `CMP` 和条件跳转指令的过程中，我们遇到了一些问题，记录如下以供参考：

1.  **解析器错误:** 最初的解析器 (`parse_ins.h`) 未能正确处理行尾的注释和操作数周围的空格，导致 `CMP CX, BX ; comment` 这样的代码被错误地解析。**解决方案:** 已通过在解析前移除注释和修剪操作数空格来修复此问题。
2.  **断言语法错误:** 测试用例一度使用了错误的断言语法，如 `;assert regs[AX] == 2` 或在末尾添加了分号。**正确语法:** 必须使用 `;assert(regs[AX] == 2)` 的形式。

遵循本指南将有助于保持测试的一致性，并减少因环境或语法误解而导致的问题。
